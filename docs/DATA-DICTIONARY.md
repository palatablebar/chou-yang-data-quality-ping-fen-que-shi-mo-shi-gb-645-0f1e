# 定义表 qualiscore

## 1 列契约

固定 10 列，顺序即单元格账的列顺序；表头按别名映射（中文表头、带空格或括号都认）。

| 列名 | 表头 | 类型 | 单位 / 刻度 | 取值范围 | 说明 |
|---|---|---|---|---|---|
| `ticket_id` | 工单号 | 字符串保形 | — | `T-YYYY-NNNNNN` 或 6-19 位数字 | 业务键；19 位大整数不过 `int()` |
| `customer_id` | 客户号 | 字符串保形 | — | 3-8 位数字 | 前导零保留，`00123` 与 `123` 是两个客户 |
| `channel` | 渠道 | 枚举 | — | 电话 / 在线 / 邮件 / 门店 | 大小写与全角先折半角再比对 |
| `created_at` | 受理时间 | 时间 | 入库 UTC，展示 +08:00 | ISO8601 | 带偏移按偏移换算；无偏移按 +08:00 |
| `first_response_min` | 首响(分钟) | 小数 | 分钟 / 0.1 | 0 – 2880 | 千分位、全角数字先归一 |
| `handle_hours` | 处理时长(小时) | 小数 | 小时 / 0.01 | 0 – 720 | 同列混写小数位时按 0.01 量化 |
| `satisfaction` | 满意度 | 整数 | 分 / 1 | 1 – 5 | 1-5 分刻度粗，离散度低于 5 判退化 |
| `agent` | 受理人 | 文本 | — | 非空 | 整列为空时记「全空列」 |
| `region` | 区域 | 文本 | — | 非空 | 与 `agent` 常同起同落，看共缺对 |
| `priority` | 优先级 | 枚举 | — | P1 / P2 / P3 | 不在枚举内记格式不合格 |

## 2 单元格状态

| 状态 | 判定 | 原因码 | 是否进缺失账 |
|---|---|---|---|
| 缺失 | 空串 | `K_NULL` | 是 |
| 缺失 | 空白串（只有空格、全角空格） | `K_BLANK` | 是 |
| 缺失 | 哨兵：`-` `--` `—` `/` `N/A` `NULL` `NONE` `未知` `无` `暂无` `待定` `空` `未填` | `K_SENTINEL_NULL` | 是 |
| 格式不合格 | 无法解析成该列类型 | `K_BAD_FORMAT` | 否，进格式账 |
| 格式不合格 | 能解析但越界（如满意度 7、首响 −3） | `K_OUT_OF_RANGE` | 否，进格式账 |
| 写法未定 | 数值的分隔符语法无法唯一确定小数位置（见第 3 节） | `K_NOTATION_UNKNOWN` | 否，不进任何比率 |
| 有值 | 解析成功且在范围内 | — | 否，进有值账 |

四条恒等式：

1. 单元格 = 缺失 + 写法未定 + 有值
2. 有值 = 合格 + 格式不合格
3. 可评单元格 = 单元格 − 写法未定（评分覆盖此范围）
4. 离群格 ⊆ 合格格（只从数值列、且该列未退化时产生）

优先级（TRAP-19 / TRAP-27）：缺失 > 格式不合格 > 写法未定 > 离群。
一个单元格只拿到一个状态与一个原因码。

## 3 数值写法裁定

附件不保证带地区说明，同一列可能混写 `1,204.5` 与 `1.204,5`。逐 token 用语法
本身证明小数位置，不按列猜地区，也不逐个猜测：

| 原值 | 成立的读法 | 结果 |
|---|---|---|
| `1,204.5` | 美式 1204.5（欧式语法不成立：分组后不能再有点号） | 有值 1204.5，记 `us` |
| `1.204,5` | 欧式 1204.5（美式语法不成立） | 有值 1204.5，记 `eu` |
| `1,204` | 美式 1204 与欧式 1.204 都成立 | 写法未定，不取值 |
| `1.204` | 欧式 1204 与无分隔读法 1.204 都成立 | 写法未定，不取值 |
| `1 204.5` | 空格只作分组，美式 1204.5 | 有值 1204.5 |
| `12,34.5` | 无成立读法 | 格式不合格 |

- 只有一种读法成立时直接取值；两种读法都成立且数值相同（如 `1204.5`）按中性记。
- 两种读法都成立但数值不同 → `K_NOTATION_UNKNOWN`：不给值，**不进缺失维、格式维、
  离群维与评分的任何分子或分母**，只在画像、报告页与 `notation.csv` 留原值、行号
  与两种读法。未证实的解释不进入分数。
- 即使其中一种读法被列契约排除（越界、整数列出现小数），也不按合格的那一侧取值：
  取值仍依赖未证实的写法，同样判写法未定（例如 1-5 分列里的 `1.000`，可能是 1，
  也可能是千分位 1000）。只有两种读法**都**不合格时，结论与写法无关，才记格式不合格。
- 写法未定的格在重复哈希里用 `?` + 原值参与：同一原文仍可判重，不同原文不会
  因为「都未定」被合并。
- 裁定策略是 `config.NOTATION_POLICY`，参与规则摘要；改策略必须换 `RULE_VERSION`，
  否则同输入会复用旧运行记录。

## 4 时间

- 入库统一 UTC（`+00:00`），页脚与页面按 `Asia/Shanghai (+08:00)` 显示。
- `Z` 结尾、`+08:00`、无偏移三种写法都归一到同一时刻；无偏移按单据本地时区 +08:00 处理。
- 运行记录时间戳用 UTC ISO8601 秒级；表格里显示本地时间。

## 5 去重键

| 账 | 键 | 用途 | 与另一账的关系 |
|---|---|---|---|
| 全行哈希 | 10 列规范化后整行的 sha256 | 「采纳行 = 唯一 + 重复」 | 决定重复率与重复维扣分 |
| 业务键 | `ticket_id` | 同键重复、同键冲突 | 只做归因，不改变行账 |

- 缺失格参与哈希时用固定占位符 `\u0000MISSING`，避免「都缺这一列」被当成不同行。
- 格式不合格格用 `!` + 原值参与哈希，保证同一份坏数据两次运行哈希一致。
- 同键不同值：两行都保留原值，冲突列逐列列出；系统不猜哪条为准。

## 6 评分常量

| 维度 | 封顶分 | 容忍度 | 比率分母 | 说明 |
|---|---:|---:|---|---|
| 缺失 | 30 | 8% | 可评格 | 缺失格 /（单元格 − 写法未定）；写法未定格不进分子也不进分母 |
| 重复 | 25 | 6% | 采纳行 | 全行重复行 / 采纳行 |
| 离群 | 20 | 10% | 参检格 | 离群格 / 参检格（已排除退化列与写法未定格） |
| 格式 | 25 | 5% | 可评且非缺失格 | 格式不合格格 /（单元格 − 写法未定 − 缺失） |

- 每维扣分 = 封顶分 × min(1, 实际比率 ÷ 容忍度)，量化 0.01（ROUND_HALF_UP）。
- 总分 = 100 − 扣分之和，量化 0.01，恒在 [0, 100]；`总分 + 扣分之和 = 100` 逐位成立。
- 可评范围：`cells_assessable = 单元格总数 − 写法未定`；缺失仍属可评范围（按缺失维计）。
  报告页、`/api/score`、`assessable.csv` 与 `manifest.json` 同源展示这个范围，
  并给出未定格的原始行号；未证实解释不进入分数。
- 可评覆盖率 = `可评格 ÷ 单元格`；低于 `NOTATION_COVERAGE_MIN`（默认 95%）时分数
  照算，但结论标「仅覆盖可评格」并列出原因，避免「整列未定 → 100 分 A 级」的误读。
- 写法未定格为 0 时，缺失维分母就是单元格总数、格式维分母就是有值格，
  与引入写法未定之前的口径逐位一致（脏样例仍是 65.24 分）。
- 等级：A ≥ 90、B ≥ 75、C ≥ 60、其余 D；等级标签依次为可用 / 待复核 / 需返工 / 不可用。
- 严重度 = 该维扣分 ÷ 该维封顶分：≥ 0.60 严重、≥ 0.30 警告、> 0 提示、0 通过。

## 7 稳健离群

- 中位数：偶数个取中间两值均值；`MAD = median(|x − 中位数|)`。
- `z = 0.6745 × (x − 中位数) / spread`，阈值 `|z| > 3.5`。
- MAD = 0 时 `spread = 0.6745 × IQR / 1.349`（等价于 `z = 1.349 × (x − 中位数) / IQR`）。
- `spread` 低于「列刻度 × 5」或 MAD 与 IQR 同为 0 → 该列判退化，标 `K_DEGENERATE`，不产生离群格。
- 参检样本少于 4 个 → 方法记 `insufficient`，同样不产生离群格。

## 8 缺失模式

- 连续缺失段：同一列按原始行序连续缺 ≥ 3 个单元格记一段，起止都用源文件行号。
- 缺失签名：一行里缺失列名的有序元组；同签名行数 ≥ 1 即进模式表。
- 共缺对：两列在同一行同时缺失 ≥ 2 行才记一对。
- 全空列：整列 100% 缺失，单独标出，不算「填充率低的列」。

## 9 运行记录

| 字段 | 含义 |
|---|---|
| `run_id` | `QS-<UTC 时间戳>-<4 位随机>`，一次运行一个 |
| `input_digest` | 文件名 + 文件字节 sha256 + 规则版本与阈值摘要 的 sha256 |
| `rules_digest` | 权重、容差、等级阈值、稳健系数与数值写法裁定策略的摘要 |
| `version` | 同名数据集自增版本号，陈旧提交靠它拦 |
| 幂等键 | (`数据集名`, `input_digest`, `rule_version`) 唯一，重复运行直接复用 |
| `snapshot_sha256` | 完整结果快照的 sha256；读取时逐条校验 |

### 重试与恢复

- **同一附件重试不重复计分**：命中幂等键只刷新「最近查看」，返回同一条运行记录；
  记录数、版本号、分数都不变。
- **写入原子**：新版本的数据集原文与运行记录在同一事务提交；任一步失败整体回滚，
  返回 `E_STORAGE`，旧版原文与旧版完整快照保持不动。
- **快照损坏回退**：读取时先校验 sha256；最新一条快照损坏时按「同数据集版本倒序」
  回退到最近一条完整旧版，页面顶部、`/api/score/latest`、`/api/runs/{id}` 与
  `manifest.json` 的 `fallback` 都标明损坏的 run_id、回退到的 run_id 与原因。
  坏记录保留未删；只有全部快照都读不出时才返回 `E_SNAPSHOT`，绝不显示半截报告。
- **损坏后重跑**：同一输入重跑会在原 run_id / 原版本上重算并重写快照（`repaired`），
  不新增记录。
- 老库没有 `snapshot_sha256` 列时启动自动补算摘要，历史记录不会被判成损坏。

## 10 原因码

完整清单见 `app/reasons.py`，前缀含义：`E_` 文件级失败（4xx，整批不落数据）、
`Q_` 行级隔离（进隔离区，带行号与原值）、`K_` 标记（不进隔离区，只留证据）。
